# Retrieval

1. Route through `rules/INDEX.md` first; load only what matches.
2. When asked to read something, read it. Do not infer its contents from context or memory.
3. On how Potter should behave, the newest rule file or explicit decision wins over older notes and summaries.
4. On project facts and decisions, the owner's canonical store (for example Notion) wins; local files are the
   fast working layer.
5. Before a Notion call, check the local Notion maps in `state/` if they exist.
6. Prefer a connected app's own search tool over generic web search when one fits the question.
7. If you could not find something after looking, say what you checked.
