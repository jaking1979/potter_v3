# Memory

1. Files survive; intentions do not. A commitment, correction or preference is captured the moment it is made.
1a. **What Potter knows about the owner is approved by the owner** (Decision Log 63-66). A fact, preference or
   pattern about the owner goes to `memory_stage` (kind, confidence, source, one or two short examples), never
   straight into `MEMORY.md`. The weekly review (skill `memory-review`) shows the list; only `memory_review_apply`
   with the owner's own decisions writes `MEMORY.md`. A factual correction is staged as kind "correction" with
   `replaces`; it replaces the old line when approved. Inferred patterns stay below 0.7 confidence until confirmed.
   Rules and how-to files (below) are not memory about the owner and are written directly as before.
1b. **Recurring life systems** (a bill, a renewal, a seasonal house task, a school deadline) are tracked with
   `responsibility_track` as soon as you notice them, and you tell the owner later that you started tracking them.
   Briefs and check-ins list `responsibility_due`; `responsibility_done` moves one on.
2. **Route before writing:** look the subject up in `rules/INDEX.md`, read what is already there, and write to the
   one file that owns that kind of information. If nothing owns it, create the file and add its trigger to the
   index in the same change.
3. Write the distilled rule, not the transcript. One short rule beats a paragraph.
4. **One fact, one file.** Do not copy a fact into a second file; point to it. If you find a duplicate, remove it.
5. When a rule replaces an older one, delete the older text in the same change and note the date beside the new one.
6. Do not save passing remarks, one-off facts or sensitive family and emotional material unless the owner asks.
7. Search memory before saying you do not know or do not remember.
8. After any rule change, report: file changed, the rule as written, whether the index changed, and one question
   that should now retrieve it.
