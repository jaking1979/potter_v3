# T40 E0 — Run Economics foundation (draft, offline-only)

Source of authority: [T40 Notion engineering proposal](https://app.notion.com/p/40fa667c631681ebb148f0c4ae534bfa). Josh approved the **feature scope** and offline E0 implementation on 2026-11-05, not deployment, budgets, merging or any change to live Potter. Preserve T9/T10/T20/T25/T28 ownership and T22/T39 gates.

## What E0 currently implements
- Strict, privacy-minimal normalized model-call record; prompt/body/tool arguments and unexpected fields are rejected.
- Model/provider-specific, date-scoped supplied rate table; no embedded real prices or invented provider usage.
- Separately priced uncached input, cache-read input, cache-write input and output tokens.
- Exact reported cost kept separate from derived cost, with visible discrepancy. Missing counters or rates are **unknown**, not free.
- Task tree rollup counting uniquely identified model calls (including children) once; no summing parent snapshots into parent.
- Preflight low/likely/high cost scenarios from explicit caller-supplied hypotheses, always labeled heuristic rather than an exact price.
- Node built-in synthetic tests run with: `node --test test/economics.test.mjs`

## Deliberate limits
- There is no OpenClaw/OpenRouter/Anthropic/DeepSeek live adapter, metering hook, provider price sync, billing reconciliation, policy gate, budget enforcement, logging storage, UI, monitoring, synthetic cache ping, auto-routing, schedule, or live deployment. Nothing accesses secrets or external data.
- `input_tokens` in the normalized contract **must include** cached input. Provider adapters must prove that convention; do not copy vendor fields naively.
- Cache-read/write tokens are required when calculating an estimate (explicit 0 if known). Missing/null means unknown even when other counts are known.
- Token pricing assumes standard per-million-token rates and that provider's output token counter already represents the billable output class. Reasoning/image/audio/tool charges need later explicit rules, not hidden zeroes.
- Date-based rate matching prevents using rates not yet effective or expired, but E0 does not independently verify that the supplied prices are correct or authoritative.
- Floating-point USD is rounded to 9 decimals for this prototype; positive amounts below its representable resolution are unknown rather than reported as free. Per-call rounding still loses precision on accumulation; exact decimal/minor-unit accounting and multi-currency require follow-up.
- Provider cost report is separately observed; E0 sums derived estimates, not official invoices.
- Rollup trusts its supplied task lineage and call IDs; T9/T10 must own authenticated identity, durable deduplication, crash/retry reconciliation and cross-process safety.
- No hard budget, cache-retention, router or provider changes until reviewed with the PolicyEngine and tested against real provider characteristics.
