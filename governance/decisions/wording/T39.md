<b>Exact wording:</b> “Repository integrity is enforced at consumption, not by GitHub. Author and opposite reviewer each sign an attestation with an SSH signature (namespace <code>potter-review</code>) over the commit SHA, tree hash, decision-manifest hash, evidence hash, role, verdict, nonce and expiry. Each agent's private key exists only in its own platform's secret store; the hosts hold pinned public keys only. A merge receipt is valid only with two distinct-key attestations (author ≠ reviewer), all required checks green, no open REQUEST CHANGES, and an unexpired, unconsumed nonce. CI and the host gate both verify receipts. The release builder and updater refuse any commit without a valid receipt. Any unreceipted commit on <code>main</code> is a security incident: it is alerted, reverted, and blocks release. Changing the key set requires Josh's one-tap approval.”

<b>Acceptance tests:</b> (1) a direct push to <code>main</code> is flagged within 1 h and is never deployable; (2) same-key self-review is rejected; (3) a replayed or expired attestation is rejected; (4) a commit added after review voids the receipt; (5) a forged signature from the host's key material fails; (6) a revoked key fails, while archived receipts still verify.
