# T38 · Agent-owned computer workspace

Status: RATIFIED by Josh 2026-11-01 (AGREED 2026-10-31).
Source: Notion 04 · v3 Design Council, T38 Decision & Reconciliation Record.

## Wording

`browser`, `computer` and `messages.send_as_josh` are separate registry capabilities, each host-bound and runtime-disabled until enabled by policy. Order: connector/API → browser (OptiPlex, managed headless profile) → computer (M1, OpenClaw node). Potter runs in its own standard (non-admin) macOS user with its own Apple ID. Josh's Apple ID is preferably signed out of the M1; otherwise it lives in a separate macOS user that stays logged out unless `messages.send_as_josh` is enabled. The computer agent never runs in Josh's user; Messages.app is denylisted for `computer.act`. Every consequential browser or computer step goes through the PolicyEngine, with a screenshot on the approval card. Arming a window is never approval for an act. Workstation output carries T11/T12 taint. Kill state disarms within 5 s. If the M1 is offline, computer tasks pause and are offered as Do-it-myself; browser and shell continue. After a crash, an unknown outcome is reconciled from a fresh screenshot per T10, never by blind retry. `messages.send_as_josh`: one fixed entry point in Josh's user that accepts only recipient and text. It needs a fresh per-message approval bound to the exact recipient and text, and any change voids it. Each send gets a durable receipt. Reads are limited to a Josh-named thread and the minimum context for that send. Message content cannot grant authority. S13's negative test stays in force for the Potter identity.

## Acceptance tests

1. Josh's seven tasks, 10 runs each per host. The primary needs ≥90% success on every task.
2. 5 forced reboots and 5 sleep cycles return to ready without Josh, or the manual unlock is alerted within 5 min.
3. Kill state disarms `computer` within 5 s.
4. Negative tests: the Potter user cannot read Josh's home folder, keychain, Messages or iCloud data, the EHR domains, or vault secrets beyond those injected.
5. A forced crash mid-step is reconciled with no duplicate action.
6. If `messages.send_as_josh` is pursued: 10 approved sends to Josh's own test thread, with no loss or duplicates. An edited-text replay is rejected. The send works while Potter's user is the active GUI session. There is no read outside the named thread.
